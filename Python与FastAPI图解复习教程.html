CHAPTER 01

01｜找回开发环境与执行感觉

目标： 能独立运行一个 Python 文件，知道项目的解释器、依赖装在哪里，以及如何定位执行入口。

Python 是一门动态类型语言。你不需要提前声明每个变量的类型，但运行时对象仍然有类型。通常你把业务逻辑写进 .py 文件，由解释器执行；导入第三方包时，解释器从当前环境的模块搜索路径里寻找它。

1.1 环境准备（Windows / Anaconda / PyCharm）

推荐复用 Python 3.11，避免一开始就在环境问题上浪费时间。若 C 盘空间有限，可在 Anaconda Prompt 创建 D 盘环境：

BASH
conda create --prefix D:\envs\pyrefresh python=3.11 -y
conda activate D:\envs\pyrefresh
python --version
python -m pip --version
where python

PyCharm 中选择已有解释器 D:\envs\pyrefresh\python.exe，在 IDE 中编辑、运行文件；安装依赖时使用已激活的终端。若已有合适环境，不必新建。python -m pip 使 pip 对应当前 Python，避免装到了另一个环境。

1.2 第一个文件 hello.py

PYTHON
name = 'Python'
print(f'Hello, {name}!')
BASH
python hello.py

输出 Hello, Python!。普通语句通常从上到下执行；定义函数时函数体不会立即运行，调用才运行。程序出错时，先从 Traceback 最后一行读异常类型和描述，再往上找自己项目中的文件与行号。

1.3 IDE 调试的最短路径

在业务代码行左侧打断点，选择 Debug。Step Over（F8）执行当前行，Step Into（F7）进入函数，Step Out（Shift+F8）退出当前函数（快捷键以 IDE 配置为准）。变量窗口可以检查参数、字典内容和返回值。不要只靠肉眼猜代码会怎么跑。

动手验收

运行 hello.py；修改 name 并重新运行；故意写错变量名，观察 NameError，再修复。

CHAPTER 02

02｜基本语法：变量、类型、运算与字符串

目标： 读懂接口参数、变量赋值、字符串拼接和类型转换。

2.1 变量是名字，对象才存数据

PYTHON
name = '检查服务'    # str 字符串
count = 3           # int 整数
latency = 0.35      # float 浮点数
healthy = True      # bool 布尔值
error = None        # NoneType：没有值
print(type(count), type(error))

赋值是把名字绑定到对象，并非每次都复制数据。None 不等于空字符串、0 或空列表。检查没有值推荐 value is None。== 比较值，is 比较是否同一对象，不要用 is 比较普通字符串或数字值。

2.2 运算与真假判断

运算 含义 示例
+ - * / 加减乘除 5 / 2 得 2.5
// % ** 向下取整除法、余数、乘方 5 // 2 得 2
== != >= <= 值比较 3 >= 2 为 True
and or not 逻辑运算（有短路） True and False
in 成员检查 'done' in statuses
PYTHON
count = 0
if not count:
    print('没有任务')
value = None
if value is None:
    print('尚未设置')

0、None、False、空字符串、空集合通常是假值，但含义不同。例如用户允许 priority=0 时，不应使用 if not priority 判断没传参数。

2.3 字符串、切片、格式化

PYTHON
text = '  FastAPI:OK  '
clean = text.strip()
parts = clean.split(':')
print(parts)                 # ['FastAPI', 'OK']
print(clean[:7])             # FastAPI
print(clean[-2:])            # OK
print(clean.lower())         # fastapi:ok
print(' / '.join(parts))     # FastAPI / OK
print(f'{parts[0]} 状态：{parts[1]}')

切片 s[start:stop:step] 左闭右开，索引从 0 起。字符串不可变，strip() 返回处理结果，不会原地改写原字符串。f-string 常用于日志、提示语和 URL；不要用它直接拼接不可信输入到 SQL 语句。

2.4 类型转换

PYTHON
raw = '120'
latency_ms = int(raw)
ratio = float('0.8')
print(latency_ms + 30)       # 150
print(str(latency_ms))       # '120'
print(bool('False'))         # True：非空字符串

int('abc') 会抛出 ValueError。HTTP 查询参数原本是文本，而 FastAPI 会按声明的类型解析并校验，这也是学习类型转换的实际用途。

动手验收

将 ' 200 ' 转为整数，判断是否等于 200；将 database:failed 拆成服务名和状态。答案：int(raw.strip()) == 200，以及 name, status = text.split(':')（确保恰好两段）。

CHAPTER 03

03｜数据结构：列表、字典、元组、集合

目标： 读懂业务 JSON、任务列表、缓存映射，能增删改查与筛选。

类型 形象理解 特性 典型场景
list 排队的任务 有序、可变、允许重复 搜索结果、消息列表
dict 编号对应档案 键唯一且可哈希；保留插入顺序 用户信息、JSON 对象
tuple 固定的一组信息 有序、不可变 坐标、函数多返回值
set 去重名单 不保证顺序，元素可哈希 去重、权限集合

3.1 list：一组有顺序的数据

PYTHON
tasks = ['检查数据库', '检查 Agent']
tasks.append('生成报告')
tasks.insert(1, '读取日志')
print(tasks[0])          # 检查数据库
print(tasks[-1])         # 生成报告
print(tasks[1:3])        # ['读取日志', '检查 Agent']
tasks[0] = '测试数据库'
last = tasks.pop()       # 移除并返回末尾元素
tasks.remove('读取日志')
print(tasks)             # ['测试数据库', '检查 Agent']

append 加单个元素，extend 展开可迭代对象；sort() 原地排序并返回 None，sorted() 创建新列表。pop 索引不存在会报 IndexError，remove 找不到值会报 ValueError。列表成员查找通常 O(n)。

3.2 dict：用键查数据

PYTHON
task = {'id': 1, 'title': '诊断', 'status': 'pending'}
print(task['title'])
print(task.get('priority', 2))  # 没有这个键则返回默认值
task['status'] = 'running'
task['priority'] = 1
for key, value in task.items():
    print(key, value)
task.pop('priority', None)

task['missing'] 抛 KeyError；get 不会，但也要考虑结果可能是 None。字典平均按键查找 O(1)，适合按任务 ID 查询。键通常是字符串、整数或满足可哈希条件的元组。字典的 keys()、values()、items() 是视图，不是普通列表。

3.3 tuple 与 set

PYTHON
point = (120, 80)
x, y = point
single = (1,)              # 单元素元组必须带逗号
roles = {'reader', 'admin', 'reader'}
roles.add('editor')
roles.discard('unknown')   # 不存在也不报错
required = {'admin', 'editor'}
print(required <= roles)  # True：是否为子集
print(roles & {'admin', 'guest'})  # {'admin'}

元组内部如果包含列表，列表本身仍可变；元组不能重新绑定其位置。空集合用 set()，{} 是空字典。

3.4 嵌套结构：后端最常看到的形状

PYTHON
tasks = [
    {'id': 1, 'title': '数据库', 'status': 'done'},
    {'id': 2, 'title': 'Agent', 'status': 'pending'},
]
print(tasks[1]['title'])        # Agent
for task in tasks:
    if task['status'] == 'pending':
        print(task['id'], task['title'])
pending = [t for t in tasks if t['status'] == 'pending']
by_id = {t['id']: t for t in tasks}
print(by_id[2]['status'])        # pending

阅读口诀：先看最外层 [] 还是 {}，再看每个元素是什么。列表推导式就是“生成元素 + 遍历 + 可选筛选”；太复杂时换成普通 for。

3.5 可变对象与浅拷贝：最容易出现的隐蔽 bug

PYTHON
from copy import deepcopy
source = {'tags': ['urgent']}
a = source
b = source.copy()
c = deepcopy(source)
a['tags'].append('db')
print(source, b, c)  # source 和 b 的 tags 都多了 db；c 不变

赋值共享原对象；浅拷贝只复制外层容器；深拷贝递归处理内部对象（并不保证所有类型都能复制）。函数参数也通过对象引用传递，修改共享列表会影响调用方。

3.6 栈、队列、排序

PYTHON
from collections import deque
stack = []
stack.append('step1')
stack.append('step2')
print(stack.pop())          # step2，后进先出
queue = deque(['job1', 'job2'])
queue.append('job3')
print(queue.popleft())      # job1，先进先出
items = [{'priority': 3}, {'priority': 1}]
print(sorted(items, key=lambda x: x['priority']))

deque 两端插入/弹出通常 O(1)，避免频繁 list.pop(0) 搬移元素。线程间通信与异步协程通信分别考虑 queue.Queue、asyncio.Queue，普通 deque 不提供这些等待机制。

动手验收

从上面的 tasks 找出未完成任务的 ID 列表；构建 ID 到任务的字典，并更新 ID=2 的状态。参考：[t['id'] for t in tasks if t['status'] != 'done']；by_id[2]['status'] = 'done'（它也修改原列表中共享的字典）。

CHAPTER 04

04｜流程控制：条件判断与循环

目标： 知道代码为什么进入某个分支、何时跳过、何时终止。

4.1 if / elif / else

PYTHON
status = 'failed'
if status == 'done':
    print('结束')
elif status == 'failed':
    print('记录异常，等待处理')
else:
    print('还在执行')

每条分支按顺序判断，只执行第一个符合条件的分支。缩进表示代码块，建议 4 个空格。冒号不能省略。多个独立 if 则可能执行多个分支。

4.2 for、range、enumerate、zip

PYTHON
names = ['db', 'agent', 'api']
for name in names:
    print(name)
for i in range(3):
    print(i)                 # 0, 1, 2
for i, name in enumerate(names, start=1):
    print(i, name)
for name, state in zip(names, ['ok', 'failed', 'ok']):
    print(name, state)

zip 默认在较短序列耗尽时停止。range(start, stop, step) 不包含 stop。enumerate 能避免手写下标变量。

4.3 while、break、continue

PYTHON
attempt = 0
while attempt < 3:
    attempt += 1
    if attempt == 1:
        continue     # 跳过当前轮剩余逻辑
    print(f'第 {attempt} 次检查')
    if attempt == 2:
        break        # 退出最近的一层循环

这里仅打印第 2 次。pass 不做任何事，只是语法占位。while 必须有退出条件；实际重试还需要只针对可重试错误、设置超时和退避，不能无限循环。

4.4 业务场景：统计异常服务

PYTHON
services = [{'name': 'db', 'ok': True}, {'name': 'agent', 'ok': False}]
failed = []
for item in services:
    if item['ok']:
        continue
    failed.append(item['name'])
print(failed)   # ['agent']
动手验收

添加第三条失败记录；用列表推导式重写 failed。参考：[s['name'] for s in services if not s['ok']]。

CHAPTER 05

05｜函数、参数、作用域与类型注解

目标： 能读懂 Service 方法签名，自己拆出职责明确的函数，并知道返回数据从哪里来。

5.1 函数定义、调用、返回

PYTHON
def build_message(name: str, status: str = 'ok') -> str:
    return f'{name}: {status}'

result = build_message('database')
print(result)                        # database: ok
print(build_message(status='failed', name='agent'))

定义时参数是占位，调用时传入实参。return 把结果交还调用方并结束函数；print 只输出，没有业务返回值。未显式返回值的函数返回 None。两个值 return a, b 实际返回元组，可以用 a, b = func() 解包。

5.2 参数传递：默认值、可变参数、解包

PYTHON
def log_event(event, *args, level='INFO', **kwargs):
    print(event, args, level, kwargs)

log_event('task', 1, 2, level='WARN', user='alice')
# task (1, 2) WARN {'user': 'alice'}
data = {'name': 'agent', 'status': 'ok'}
print(build_message(**data))

*args 将多余位置参数收进元组，**kwargs 将多余关键字参数收进字典。调用时 *items 或 **data 是解包。level 在这里是仅限关键字参数。读第三方库时经常遇见这些形式，不需要所有函数都这样写。

5.3 默认参数陷阱

PYTHON
def add_tag(tag, tags=None):
    if tags is None:
        tags = []
    tags.append(tag)
    return tags
print(add_tag('db'))      # ['db']
print(add_tag('agent'))   # ['agent']

不要把 tags=[] 当默认参数：默认表达式在函数定义时求值一次，多次调用可能共享列表。避免用 tags = tags or [] 代替 None 判断，因为传入的空列表也可能需要被保留。

5.4 作用域与闭包

PYTHON
def make_counter():
    count = 0
    def increment():
        nonlocal count
        count += 1
        return count
    return increment

counter = make_counter()
print(counter(), counter())  # 1 2

函数先查局部变量，再查外围函数、模块全局、内置名称（LEGB）。闭包可以保留外围函数的变量绑定，即使外层函数已经返回。nonlocal 修改外围函数中的绑定；global 操作模块全局绑定。日常业务尽量用显式参数和返回值，不滥用全局可变状态。

5.5 类型注解（FastAPI 必修）

PYTHON
def find_task(task_id: int, tasks: dict[int, str]) -> str | None:
    return tasks.get(task_id)

print(find_task(1, {1: '检查数据库'}))

list[str] 表示字符串列表；str | None 表示两种可能类型（Python 3.10+）。普通 Python 注解本身通常不会强制校验类型，FastAPI/Pydantic 会读取注解执行验证或生成接口文档。

动手验收

写 is_failed(status: str) -> bool，在列表推导式中调用。参考：return status == 'failed'。

6.2 文件、JSON 与上下文管理器

PYTHON
import json
from pathlib import Path
path = Path('tasks.json')
with path.open('w', encoding='utf-8') as f:
    json.dump([{'id': 1, 'title': '诊断'}], f, ensure_ascii=False, indent=2)
with path.open(encoding='utf-8') as f:
    tasks = json.load(f)
print(tasks[0]['title'])
text = json.dumps(tasks, ensure_ascii=False)
print(json.loads(text))

dump/load 对文件，dumps/loads 对字符串。with 在退出代码块时调用资源的退出逻辑，即使发生异常也通常会释放文件等资源。相对路径是相对当前工作目录，不一定是 .py 所在目录。

6.3 try / except / else / finally / raise

PYTHON
def parse_priority(raw: str) -> int:
    try:
        value = int(raw)
    except ValueError as exc:
        raise ValueError('priority 必须是整数') from exc
    if not 1 <= value <= 3:
        raise ValueError('priority 必须在 1~3 之间')
    return value

try:
    print(parse_priority('abc'))
except ValueError as exc:
    print(f'参数错误：{exc}')
else:
    print('业务成功')
finally:
    print('检查结束')

except 捕获匹配类型的异常，else 在 try 正常完成时执行，finally 用于收尾。raise 把错误向上抛；不要用裸 except: pass 吞掉故障。捕获异常的位置应该有能力处理、转换或记录它。

6.4 logging：从打印到可定位的日志

PYTHON
import logging
logging.basicConfig(level=logging.INFO,
    format='%(asctime)s %(levelname)s %(name)s %(message)s')
logger = logging.getLogger(__name__)
try:
    task_id = int('bad')
except ValueError:
    logger.exception('invalid task id')

DEBUG < INFO < WARNING < ERROR < CRITICAL。logger.exception() 适合在 except 内记录堆栈。真实服务可带 request_id、耗时和业务 ID；不要记录 Token、密码、完整隐私数据。Traceback 先看最后一行，再定位到业务文件，再复现输入。

动手验收

创建上述两文件，运行一次；人为传入非法 ID，能够找到报错行。再将 tasks.json 改成非法 JSON，观察 JSONDecodeError。

CHAPTER 07

07｜面向对象：把状态与业务行为组织到一起

目标： 能阅读 class XxxService、self、构造函数、继承和常见方法装饰器。

7.1 类与对象

类是描述数据和行为的模板，对象是按模板创建的实例。例如任务服务持有任务字典，并提供创建、查询、修改任务的方法。函数适合无状态的独立逻辑；类适合需要共同管理的状态、依赖和行为。

PYTHON
class Task:
    kind = 'ops'                   # 类属性

    def __init__(self, title: str):
        self.title = title         # 实例属性
        self.status = 'pending'

    def finish(self):
        self.status = 'done'

    def summary(self) -> str:
        return f'{self.title}: {self.status}'

a = Task('数据库检查')
b = Task('Agent 检查')
a.finish()
print(a.summary())  # 数据库检查: done
print(b.summary())  # Agent 检查: pending

__init__ 在实例创建后初始化属性；self 指当前实例，调用 a.finish() 时 Python 自动传入 a。类属性通常由实例共享，但实例赋值可能遮蔽同名类属性。不要把每个实例独有的可变列表定义成类属性。

7.2 封装：让修改走统一入口

PYTHON
class TaskStore:
    def __init__(self):
        self._tasks = {}

    def add(self, task_id, title):
        if task_id in self._tasks:
            raise ValueError('任务 ID 已存在')
        self._tasks[task_id] = title

    def get(self, task_id):
        return self._tasks.get(task_id)

store = TaskStore()
store.add(1, '检查数据库')
print(store.get(1))

单下划线 _tasks 是内部使用约定，不是强制私有；双下划线有名称改写，也不是安全边界。通过方法统一维护规则，比任何地方随意修改字典更容易定位问题。

7.3 继承、多态、组合

PYTHON
class Notifier:
    def send(self, message):
        raise NotImplementedError

class ConsoleNotifier(Notifier):
    def send(self, message):
        print(f'[console] {message}')

class TaskRunner:
    def __init__(self, notifier: Notifier):
        self.notifier = notifier  # 组合：内部持有另一个对象

    def run(self):
        self.notifier.send('任务完成')

TaskRunner(ConsoleNotifier()).run()

继承表达 is-a（ConsoleNotifier 是一种 Notifier）；组合表达 has-a（Runner 持有 Notifier）。多态让调用方用统一接口调用不同实现。Python 还支持鸭子类型：实现所需行为即可，未必需要继承。子类扩展父类初始化时常用 super().__init__(...)。日常项目优先使用简单组合，避免为几行逻辑设计多层抽象。

7.4 实例方法、类方法、静态方法与 property

PYTHON
class Task:
    def __init__(self, title):
        self.title = title

    @classmethod
    def from_dict(cls, data):
        return cls(data['title'])

    @staticmethod
    def valid_title(title):
        return bool(title.strip())

    @property
    def short_title(self):
        return self.title[:8]

t = Task.from_dict({'title': 'database check'})
print(t.short_title)                # database
print(Task.valid_title('   '))      # False

实例方法访问 self；类方法接收 cls，常用于替代构造方式；静态方法不自动接收实例或类。property 让访问属性时执行方法。单独的工具函数也可以，不必把所有函数都塞进 class。

08｜装饰器：理解 @app.get 与通用增强逻辑

目标： 看懂 @xxx 是什么，理解日志、权限、计时等横切功能为什么能包住原函数。

8.1 函数也是对象

PYTHON
def say():
    return 'hello'

other = say        # 没有括号，赋值的是函数对象
print(other())     # 有括号，执行函数

函数可以被传参、返回或存入变量。装饰器利用这点接收原函数并返回新对象，常见做法是返回包装函数。

8.2 手写一个计时装饰器

PYTHON
from functools import wraps
from time import perf_counter

def timed(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        start = perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f'{func.__name__}: {perf_counter() - start:.4f}s')
    return wrapper

@timed
def add(a, b):
    return a + b

print(add(2, 3))

@timed 在定义阶段大致等价于 add = timed(add)；调用阶段执行 wrapper，再执行原函数。wraps 保留名称、文档及原函数引用等信息，方便调试与签名检查。wrapper 必须返回业务结果，否则调用方拿到 None。finally 确保异常时仍输出计时。

8.3 带参数的装饰器与 async 包装

PYTHON
from functools import wraps

def trace(label):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            print(label)
            return func(*args, **kwargs)
        return wrapper
    return decorator

@trace('检查任务')
def check():
    return 'ok'
print(check())

对于异步函数，通常要写 async def wrapper(...) 并 return await func(...)，而不是用同步 wrapper 返回尚未等待的协程来计算耗时。多个装饰器的应用从下往上：@A @B 相当于 f = A(B(f))。

8.4 FastAPI 路由装饰器不是简单的日志包装

PYTHON
from fastapi import FastAPI
app = FastAPI()

@app.get('/health')
def health():
    return {'status': 'ok'}

这里 app.get('/health') 返回装饰器；定义 health 时登记 HTTP 方法、路径与处理函数等路由信息。HTTP 请求到来时框架匹配路由，再调用处理函数。并非“导入文件就执行 health”。多个普通装饰器叠加到接口时注意签名、异步属性与注册顺序；FastAPI 的依赖注入通常比自制权限装饰器更适合做接口依赖。

动手验收

给 timed 装饰一个有关键字参数的函数，确认返回值保留；再把函数内部改成抛异常，确认计时仍输出且异常没有被吞掉。

09｜迭代器、生成器与流式传输的基础

目标： 看到 yield 不再陌生，知道为什么流式输出不一定要等所有数据生成完。

9.1 iterable 与 iterator

PYTHON
values = ['a', 'b']
it = iter(values)
print(next(it))  # a
print(next(it))  # b
# 再 next(it) 会抛 StopIteration

可迭代对象可以通过 iter 得到迭代器；迭代器记住下一步位置。for 会获取迭代器并不断取值，遇到 StopIteration 正常结束。

9.2 yield：暂停并在下次恢复

PYTHON
def events():
    yield 'start'
    yield 'searching'
    yield 'done'

g = events()             # 还没执行函数体
print(next(g))           # start
for event in g:
    print(event)         # searching / done

生成器按需产生数据，不必一次构建完整列表，但不是所有生成器都节省大量内存（如果内部已经加载全部数据则未必）。生成器通常只能消费一次。

9.3 异步生成器

PYTHON
import asyncio

async def progress():
    for i in range(3):
        await asyncio.sleep(0.1)
        yield f'step {i}'

async def main():
    async for event in progress():
        print(event)

asyncio.run(main())

异步生成器通过 async for 消费，适合不断产生 Agent 进度、模型 Token、网络响应分片等。不要对它直接使用普通 for 或 await 整个生成器。

动手验收

将 progress 改成输出开始、处理中和结束三种消息。说明与一次性 return 列表的区别：调用者能逐批消费，生成过程可能尚未结束。

10｜异步编程：async、await 与 asyncio

目标： 判断代码究竟是顺序还是并发执行，能正确调用异步 HTTP/API，并避免阻塞事件循环。

10.1 同步、并发和并行不是一回事

同步顺序执行像自己逐个检查服务，每个等待结束后再查下一个。异步 I/O 可以在等待一个服务响应时去调另一个；并发表示多个任务在同一时段推进，并行表示同一时刻实际执行多个任务。异步不意味着让 CPU 运算天然更快。

10.2 async / await 最小实例

PYTHON
import asyncio

async def check(name):
    print(f'开始 {name}')
    await asyncio.sleep(1)
    print(f'结束 {name}')
    return name

async def main():
    result = await check('db')
    print(result)

asyncio.run(main())

async def 定义普通协程函数（无 yield 时），调用 check('db') 得到协程对象，不会立刻执行；await 等待它的结果。等待支持异步的 I/O 时，当前任务可以挂起，事件循环调度其他可运行任务。若等待对象已就绪，也可能不发生实际切换。asyncio.run(main()) 用在独立脚本的最外层；FastAPI 已在运行事件循环，接口里直接 await，别嵌套 run。

10.3 顺序 await 与 gather

PYTHON
import asyncio
from time import perf_counter

async def check(name, delay):
    await asyncio.sleep(delay)
    return f'{name}: ok'

async def main():
    start = perf_counter()
    a = await check('db', 1)
    b = await check('agent', 2)
    print(a, b, '顺序耗时', round(perf_counter() - start, 2))

    start = perf_counter()
    results = await asyncio.gather(check('db', 1), check('agent', 2))
    print(results, '并发耗时', round(perf_counter() - start, 2))

asyncio.run(main())

顺序约 3 秒，并发约 2 秒（忽略调度开销）。gather 结果顺序与传入顺序一致，不是完成顺序。两个任务互相依赖时不能随便 gather；先获得用户 ID 再按 ID 查用户信息，就是顺序依赖。

10.4 create_task 与 TaskGroup

PYTHON
import asyncio

async def job(name):
    await asyncio.sleep(0.1)
    return name

async def main():
    # 3.11+，结构化并发：退出时等待子任务
    async with asyncio.TaskGroup() as group:
        t1 = group.create_task(job('db'))
        t2 = group.create_task(job('agent'))
    print(t1.result(), t2.result())

asyncio.run(main())

asyncio.create_task(coro) 将协程安排为任务，可以先做其他事再 await 它；要保留引用并处理异常。TaskGroup 更容易管理一组任务：某个子任务出现非取消异常时，会尝试取消其余子任务，最终通常以 ExceptionGroup 报告。gather 默认传播首个异常，但不会因此自动取消其他子任务。选型取决于失败后其他任务是否应继续。

10.5 超时、取消与并发限制

PYTHON
import asyncio

async def slow():
    await asyncio.sleep(1)

async def main():
    try:
        await asyncio.wait_for(slow(), timeout=0.2)
    except TimeoutError:
        print('超时，进入降级逻辑')

asyncio.run(main())

超时会尝试取消被等待任务，并等待取消处理，因此实际返回时间可能超过设置的秒数。不要随意吞掉 CancelledError；清理资源可放 finally。访问外部 API 时要设置超时、有限重试与并发限制。

PYTHON
import asyncio

async def main():
    sem = asyncio.Semaphore(2)
    async def check(i):
        async with sem:
            await asyncio.sleep(0.1)
            return i
    print(await asyncio.gather(*(check(i) for i in range(5))))

asyncio.run(main())

信号量最多允许两个任务同时进入保护区。它限制并发数量，不等于严格每秒请求次数限制；也不会自动限制创建出来的协程数量。

10.6 最危险的错误：在 async def 中直接做阻塞 I/O

PYTHON
import asyncio
import time

# 错误示范：阻塞事件循环线程
async def bad():
    time.sleep(1)

# 正确：异步等待
async def good():
    await asyncio.sleep(1)

# 已有同步 I/O 库，无法替换时可移到线程
async def bridge():
    await asyncio.to_thread(time.sleep, 1)

requests.get()、同步数据库查询、time.sleep 都可能阻塞当前线程；宣称 async 并不会自动将它们变成非阻塞操作。I/O 任务优先使用原生异步库；同步 I/O 适合线程池；大量纯 Python CPU 计算考虑进程池或独立计算服务。在常规 CPython 3.11 中，GIL 会限制多线程同时执行 Python 字节码的能力。

10.7 asyncio.Queue：生产者与消费者解耦

PYTHON
import asyncio

async def main():
    queue = asyncio.Queue(maxsize=2)

    async def producer():
        for event in ['start', 'search', 'done']:
            await queue.put(event)
        await queue.put(None)  # 结束标记

    async def consumer():
        while True:
            event = await queue.get()
            try:
                if event is None:
                    return
                print(event)
            finally:
                queue.task_done()

    await asyncio.gather(producer(), consumer())

asyncio.run(main())

队列满时 put 等待，空时 get 等待，这是简单背压。真实 Agent SSE 还需要处理客户端断开、生产者异常、取消和清理，不能只依赖一个结束标记使消费者永远等待。

动手验收

跑 10.3 对比耗时；把 check 的 sleep 改为 time.sleep 再对比，解释为什么并发优势消失；将超时从 0.2 改为 2，观察结果。能说明什么时候不该用 gather，即通过本章。

11｜网络基础：从浏览器到服务端

目标： 理解 IP、端口、HTTP 方法、请求参数、响应码和接口调用，能判断网络错误发生在哪层。

11.1 IP、端口、DNS、TCP、TLS

概念 大白话 项目中常见表现
IP 找到网络中的目标地址 127.0.0.1 是本机回环地址
端口 找到机器上的某个网络服务 Uvicorn 常用 8000
DNS 把域名解析到地址等记录 域名解析失败不等于 API 业务失败
TCP 可靠、有序的字节流传输 连接拒绝、连接超时
TLS 加密连接并校验通信方身份等 HTTPS 证书错误
HTTP 请求与响应的应用层规范 GET /health 返回 JSON

HTTP/1.1 和 HTTP/2 常运行在 TCP 上，HTTP/3 使用 QUIC（基于 UDP）。TCP 是字节流，不保留单次 send 对应的消息边界。开发 API 通常不需要直接操作 socket，但知道这一层有助排查连接问题。

11.2 URL 是什么

http://127.0.0.1:8000/tasks/12?detail=true

HTTP 方法与路径一起决定操作语义；路径参数表示资源位置，查询参数常用于过滤、分页，JSON 请求体常用于提交结构化业务数据。Header（请求头）传递 Content-Type、Authorization 等元信息。

11.3 一次 HTTP 请求长什么样

HTTP
POST /tasks HTTP/1.1
Host: localhost:8000
Content-Type: application/json
Content-Length: 30

{"title":"check","priority":1}

示意响应：

HTTP
HTTP/1.1 201 Created
Content-Type: application/json

{"id":1,"title":"check","priority":1,"status":"pending"}

上面响应省略了传输相关的部分头字段。HTTP 请求是协议消息，而 JSON 是数据序列化格式；两者不是同一个概念。HTTP/2/3 在线路上表现形式不同，此处用易读的 HTTP/1.1 文本示意。

方法 常见用途 语义
GET 查询资源 安全、幂等（按规范语义）
POST 新建、提交动作 不保证幂等
PUT 替换目标资源状态 幂等
PATCH 部分更新 不保证幂等
DELETE 删除资源 幂等语义，不要求每次状态码相同
状态码 含义与排查
200 / 201 / 204 成功 / 已创建 / 无响应体成功
400 / 422 请求错误 / 请求内容无法处理（FastAPI 常用于校验失败）
401 / 403 未通过身份认证 / 无权限
404 / 405 找不到资源或路由 / 方法不允许
429 请求过多
500 / 502 / 503 / 504 服务内部异常 / 网关上游错误 / 服务不可用 / 网关超时

11.5 TCP 小实验（选读）

可在一个文件里运行，观察客户端和服务器的连接；只绑定本机，系统会分配空闲端口。

PYTHON
import socket
from threading import Thread

def serve(server):
    conn, _ = server.accept()
    with conn:
        data = conn.recv(1024)  # 演示：可能只读到部分字节
        conn.sendall(data)

with socket.socket() as server:
    server.bind(('127.0.0.1', 0))
    server.listen(1)
    worker = Thread(target=serve, args=(server,))
    worker.start()
    with socket.create_connection(server.getsockname(), timeout=2) as client:
        client.sendall(b'hello')
        print(client.recv(1024))
    worker.join()

这只是最小 TCP 回显，实际应用协议需要消息边界处理、完整读取和异常管理。

12.3 响应模型与异常

目标： 能跟踪已有后端的 Controller/Router → Service → 数据访问链路，并安全地扩展接口。

13.1 APIRouter 与分层

Router 处理 HTTP 协议和参数，Service 管业务逻辑，Repository/DAO 封装数据访问（小项目可先由 Service 持有简单存储）。Schema 定义进出数据。FastAPI 没有强制你使用这种目录结构；目的是职责清晰而不是文件越多越好。

13.2 def 还是 async def？

场景 推荐起点
同步 SDK、同步数据库接口 普通 def 路由或明确卸载阻塞 I/O
async HTTPX、异步数据库库 async def + await
混合同步和异步 确认每次调用的性质，必要时线程卸载
长时间 CPU 任务 独立进程、进程池或任务服务

FastAPI 对普通 def 路由与普通 def 依赖通常在线程池运行；async def 路由在事件循环运行。你在代码里直接调用的普通 util/service 函数不会被框架自动卸载。不要将所有函数机械地改成 async。

13.3 中间件、资源生命周期与 CORS

中间件像包裹请求的统一入口，可记录耗时、request_id、日志等；它在业务路由外层运行。生命周期 lifespan 可初始化共享连接池，关停时释放资源。

PYTHON
from contextlib import asynccontextmanager
from fastapi import FastAPI
import httpx

@asynccontextmanager
async def lifespan(app: FastAPI):
    async with httpx.AsyncClient(timeout=5) as client:
        app.state.http = client
        yield

app = FastAPI(lifespan=lifespan)

这是独立应用示例。CORS（跨源资源共享）是浏览器访问不同源请求时的机制，开发中不同前后端端口也可能不同源。使用 CORSMiddleware 配置明确允许的源、方法和请求头；CORS 本身并非身份认证，不能靠允许或禁止跨域来保护服务端接口。

13.4 SSE：单向流式进度输出

在 basic_api.py 追加：

PYTHON
import asyncio
from fastapi.responses import StreamingResponse

async def event_stream():
    for stage in ['start', 'searching', 'done']:
        await asyncio.sleep(0.5)
        yield f'data: {stage}\n\n'

@app.get('/progress')
async def progress_api():
    return StreamingResponse(event_stream(), media_type='text/event-stream')

终端运行 curl -N http://127.0.0.1:8000/progress（PowerShell 可用 curl.exe）。客户端逐步收到事件，每个事件空行结尾。SSE 通过一个 HTTP 响应从服务端向客户端连续发送消息；WebSocket 则支持双向通信。此处只是教学流式示例，生产需考虑代理缓冲、心跳、断开、异常处理、资源释放、重连机制与授权。

本教程综合项目先使用内存字典，便于把注意力放在业务和框架。生产中通常替换成数据库：Repository 查询数据、Service 确定事务范围、Schema 与 ORM 模型明确转换；同步 ORM 不要直接阻塞异步路由，异步 ORM 使用合适的驱动与 AsyncSession。SQL 参数化、事务提交回滚、迁移管理、唯一约束与连接池都需要单独验证。不要将内存字典称为持久化或跨进程共享存储。

14.2 schemas.py：先定义请求和响应

PYTHON
from typing import Literal
from pydantic import BaseModel, Field

Status = Literal['pending', 'running', 'done', 'failed']

class TaskCreate(BaseModel):
    title: str = Field(min_length=1, max_length=100)
    priority: int = Field(default=2, ge=1, le=3)

class TaskUpdate(BaseModel):
    status: Status

class TaskOut(TaskCreate):
    id: int
    status: Status = 'pending'

TaskCreate 校验前端输入；TaskOut 继承创建数据结构并加上 id/status；TaskUpdate 只允许四种状态。不是数据库 ORM 模型。创建时的默认状态是 pending，当前版本没有限制状态流转方向。

14.3 service.py：数据与业务逻辑

PYTHON
from threading import Lock
from .schemas import TaskCreate, TaskOut, Status

class TaskService:
    def __init__(self):
        self._tasks: dict[int, TaskOut] = {}
        self._next_id = 1
        self._lock = Lock()

    def create(self, data: TaskCreate) -> TaskOut:
        with self._lock:
            task = TaskOut(id=self._next_id, **data.model_dump())
            self._tasks[task.id] = task
            self._next_id += 1
            return task

    def get(self, task_id: int) -> TaskOut | None:
        with self._lock:
            return self._tasks.get(task_id)

    def list(self, status: Status | None = None) -> list[TaskOut]:
        with self._lock:
            return [t for t in self._tasks.values()
                    if status is None or t.status == status]

    def update(self, task_id: int, status: Status) -> TaskOut | None:
        with self._lock:
            task = self._tasks.get(task_id)
            if task is None:
                return None
            updated = task.model_copy(update={'status': status})
            self._tasks[task_id] = updated
            return updated

    def delete(self, task_id: int) -> bool:
        with self._lock:
            return self._tasks.pop(task_id, None) is not None

字典使用整数 ID 作键。Lock 将短小的共享内存读写串行化，避免本进程多个线程竞争自增 ID；返回对象在本例中不再原地修改，更新使用新模型替换。model_copy(update=...) 不会重新校验更新值，这里 status 已由 Pydantic 请求模型验证。生产多进程需要共享数据库及对应并发控制，不能靠这个 Lock。

14.4 routes.py：从 HTTP 到 Service

PYTHON
from fastapi import APIRouter, Depends, HTTPException, Response
from .schemas import TaskCreate, TaskUpdate, TaskOut, Status
from .service import TaskService

router = APIRouter(prefix='/tasks', tags=['tasks'])
service = TaskService()

def get_service() -> TaskService:
    return service

@router.post('', response_model=TaskOut, status_code=201)
def create_task(data: TaskCreate, svc: TaskService = Depends(get_service)):
    return svc.create(data)

@router.get('', response_model=list[TaskOut])
def list_tasks(status: Status | None = None,
               svc: TaskService = Depends(get_service)):
    return svc.list(status)

@router.get('/{task_id}', response_model=TaskOut)
def get_task(task_id: int, svc: TaskService = Depends(get_service)):
    task = svc.get(task_id)
    if task is None:
        raise HTTPException(404, '任务不存在')
    return task

@router.patch('/{task_id}', response_model=TaskOut)
def update_task(task_id: int, data: TaskUpdate,
                svc: TaskService = Depends(get_service)):
    task = svc.update(task_id, data.status)
    if task is None:
        raise HTTPException(404, '任务不存在')
    return task

@router.delete('/{task_id}', status_code=204, response_class=Response)
def delete_task(task_id: int, svc: TaskService = Depends(get_service)):
    if not svc.delete(task_id):
        raise HTTPException(404, '任务不存在')
    return Response(status_code=204)

router 路径前缀是 /tasks，Depends(get_service) 注入同一 Service 对象。GET 的过滤参数来自查询字符串；POST/PATCH 的模型从 JSON 请求体解析；找不到 ID 统一抛 404。DELETE 成功返回 204 且无内容。

14.5 main.py：入口和模拟外部调用

PYTHON
import asyncio
import logging
from time import perf_counter
from fastapi import FastAPI, Request
from .routes import router

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)
app = FastAPI(title='任务管理 API')
app.include_router(router)

@app.get('/health')
def health():
    return {'status': 'ok'}

@app.middleware('http')
async def log_request(request: Request, call_next):
    start = perf_counter()
    try:
        response = await call_next(request)
    except Exception:
        logger.exception('request failed: %s %s', request.method, request.url.path)
        raise
    logger.info('%s %s %s %.1fms', request.method, request.url.path,
                response.status_code, (perf_counter() - start) * 1000)
    return response

async def check_component(name: str, delay: float):
    await asyncio.sleep(delay)
    return {'name': name, 'status': 'ok'}

@app.get('/diagnose')
async def diagnose():
    # 模拟两个互不依赖的外部 I/O，不是真实监控检查
    results = await asyncio.gather(
        check_component('database', 0.2),
        check_component('agent', 0.3),
    )
    return {'components': results}

app.include_router 把任务路由注册进主应用。中间件统一记录请求耗时；diagnose 中两个 check_component 是相互独立的异步等待模拟，用 gather 并发。换成真实外部服务时要设置超时、身份认证、异常策略，不要把模拟结果当真实健康状态。

14.6 一条创建请求到底如何执行？

先看路由定义：POST /tasks → 创建函数。FastAPI 校验 body 并获取依赖（这些准备步骤的内部顺序不必假定），执行 create_task，再执行 svc.create。Service 构造 TaskOut、写入字典、返回对象，框架按 response_model 生成 JSON，HTTP 201。几层存在错误就定位到对应层，不要直接重写整个项目。

14.9 模拟入职需求：自己修改旧代码

需求 A： 增加 description 可选字段。先定位 schemas.py 的 TaskCreate，添加 description: str | None = Field(default=None, max_length=300)。检查 TaskOut 继承关系、Service model_dump 的解包和响应模型；按现在的数据流，不需要到每层重复手写字段。再测试不传 description、正常传入、超长描述三种情况。

需求 C： 禁止已完成任务直接回到 pending。在 service.update 查找 task 后判断 task.status == 'done' and status == 'pending'，定义业务异常或其他明确业务错误结果，在路由层映射成 409 Conflict。测试状态冲突，确认数据没有被改写。不要把所有异常都转换为 404。

需求 D： 诊断接口模拟某组件超时。给单个外部检查加 asyncio.wait_for 和明确的 timeout 状态；考虑一个失败后其他检查是否继续。测试成功以及超时场景。不要吞掉取消异常。
