01 · JDK、JVM、main 与程序入口

P0 · 必须掌握

1. 这是什么？企业为什么用？

Java 程序不是直接把源码交给 JVM 执行：通常先由编译器 javac 转成字节码，再由 JVM 加载运行。JDK 是开发工具集合，包含编译器、运行时等。main 是普通 Java 应用的入口；public static void main(String[] args) 先按固定写法记住即可。

2. 完整可运行代码

Demo01.java · JDK 17
public class Demo01 {
    public static void main(String[] args) {
        String serviceName = "order-service";
        System.out.println("启动服务: " + serviceName);
        System.out.println("参数个数: " + args.length);
    }
}

3. 运行结果（实际执行）

启动服务: order-service
参数个数: 0

4. 代码解析与实际用途

public 表示可访问，static 表示不需要先创建对象，void 表示没有返回值，String[] args 保存命令行参数。System.out.println 输出一行；语句通常以分号结束，大括号界定代码块。下面模拟服务启动时输出环境和参数。

常见错误 / 代码审查重点文件名必须与 public 类名相同；Java 大小写敏感。IDEA 点击运行隐藏了编译步骤，不代表无需 JDK。企业项目实际入口常由 Spring Boot 接管，但这个 main 仍是基础。
动手练习 / 学会的标准将 serviceName 改成 user-service，运行后确认输出变化；再故意删除分号，读懂编译器提示的行号。

02 · 变量、基本类型与包装类

P0 · 必须掌握

1. 这是什么？企业为什么用？

变量是带名字和类型的值。Java 是静态类型语言，声明后不能随意改为另一种类型。8 种基本类型为 byte、short、int、long、float、double、char、boolean。String 是引用类型，不是基本类型。包装类 Integer、Long、Boolean 等可以存 null，也能放入泛型集合。

2. 完整可运行代码

Demo02.java · JDK 17
public class Demo02 {
    public static void main(String[] args) {
        long orderId = 100001L;
        int quantity = 3;
        boolean paid = true;
        String status = "PAID";
        Integer pageSize = null;
        int actualSize = pageSize == null ? 20 : pageSize;
        System.out.println(orderId + " " + quantity + " " + paid + " " + status);
        System.out.println("分页大小=" + actualSize);
    }
}

3. 运行结果（实际执行）

100001 3 true PAID
分页大小=20

4. 代码解析与实际用途

用户 ID 常用 Long，数量 int，是否启用 boolean，需要区分“未传”和 0 时可用 Integer。自动装箱把 int 转成 Integer，拆箱相反。long 字面量用 L；金额不要用 double 做精确计算，后面会讲 BigDecimal。

常见错误 / 代码审查重点Integer count = null; int n = count; 会因拆箱触发 NullPointerException。局部变量必须先赋值；字段有默认值。ID 不要把 long 强行缩成 int。
动手练习 / 学会的标准创建一个订单 ID、数量、支付状态和可空备注字段，打印它们；对 null 包装类先判断再拆箱。

04 · String 字符串与常用方法

P0 · 必须掌握

1. 这是什么？企业为什么用？

String 用于文本，内容不可变：调用方法通常返回新字符串，不会直接改原值。企业中常见操作为判空、去空白、按分隔符拆分、替换、查找、判断前缀。

2. 完整可运行代码

Demo04.java · JDK 17
public class Demo04 {
    public static void main(String[] args) {
        String raw = "  Alice  ";
        String name = raw.strip();
        String status = new String("PAID");
        System.out.println(name + ":" + name.length());
        System.out.println("PAID".equals(status));
        System.out.println("user,order,admin".split(",")[1]);
        System.out.println("order-service".startsWith("order"));
        System.out.println("   ".isBlank());
    }
}

3. 运行结果（实际执行）

Alice:5
true
order
true
true

4. 代码解析与实际用途

isBlank() 判断空白字符串，isEmpty() 只判断长度为 0，strip() 去除首尾空白（Java 11+），contains 查子串，split 按正则拆分。equals 比较文本内容；== 对引用类型比较是否同一对象。

常见错误 / 代码审查重点trim 或 strip 的返回值不接收就不会改变变量。split(".") 中点是正则通配符，应使用 split("\\.")。判空可以用常量在前的 "PAID".equals(status)，避免调用 null 的方法。

05 · StringBuilder 与字符串格式化

P1 · 常用进阶

1. 这是什么？企业为什么用？

StringBuilder 是可变字符缓冲区，适合循环里反复拼接。简单一次拼接用 + 就够了；String.format 或 formatted 可用于固定格式的消息。StringBuilder 本身非线程安全，通常作为方法内局部变量使用。

2. 完整可运行代码

Demo05.java · JDK 17
import java.util.List;

public class Demo05 {
    public static void main(String[] args) {
        List<String> ids = List.of("O100", "O101", "O102");
        StringBuilder sb = new StringBuilder("失败订单: ");
        for (String id : ids) {
            sb.append(id).append(' ');
        }
        System.out.println(sb.toString().strip());
        System.out.println(String.join(",", ids));
        System.out.println("共 %d 条失败记录".formatted(ids.size()));
    }
}

3. 运行结果（实际执行）

失败订单: O100 O101 O102
O100,O101,O102
共 3 条失败记录

4. 代码解析与实际用途

下方把多个失败订单号合并为一条告警消息；循环中 append，不必每次创建新的完整字符串。String.join 也常用于已有字符串列表的连接。

常见错误 / 代码审查重点不要为了所有拼接都创建 StringBuilder；不要把同一个可变 builder 作为多线程共享字段。日志框架通常用占位符参数而不是提前拼接长日志。
动手练习 / 学会的标准将分隔符改为逗号，并尝试去掉尾部多余分隔符；观察 String.join 的写法。

06 · 数组与下标

P0 · 必须掌握

1. 这是什么？企业为什么用？

数组是固定长度的同类型元素容器，下标从 0 开始。int[] ids 表示 int 数组，ids.length 是长度。数组适合固定数量、原始类型数据或某些底层接口；业务动态数据通常使用 List。

2. 完整可运行代码

Demo06.java · JDK 17
import java.util.Arrays;

public class Demo06 {
    public static void main(String[] args) {
        int[] ids = {101, 102, 103, 104};
        ids[1] = 999;
        System.out.println(ids[0]);
        System.out.println(Arrays.toString(ids));
        int[] expanded = Arrays.copyOf(ids, 5);
        System.out.println(Arrays.toString(expanded));
    }
}

3. 运行结果（实际执行）

101
[101, 999, 103, 104]
[101, 999, 103, 104, 0]

4. 代码解析与实际用途

07 · if / else 与三元运算

P0 · 必须掌握

1. 这是什么？企业为什么用？

if 根据布尔条件决定执行哪个分支。else if 用于多个互斥判断；三元表达式 条件 ? 值1 : 值2 在简单赋值时常用。企业代码倾向先处理异常情况（早返回），减少层层嵌套。

2. 完整可运行代码

Demo07.java · JDK 17
public class Demo07 {
    public static void main(String[] args) {
        int quantity = 2, stock = 5;
        String result;
        if (quantity <= 0) {
            result = "数量非法";
        } else if (quantity > stock) {
            result = "库存不足";
        } else {
            result = "允许下单";
        }
        String label = stock > 0 ? "有货" : "售罄";
        System.out.println(result + " / " + label);
    }
}

3. 运行结果（实际执行）

允许下单 / 有货

4. 代码解析与实际用途

下方对订单数量做校验，再决定状态。if 从上往下匹配，第一个成立的分支执行后不会再执行其余 else if。多个独立 if 则可能都执行。

常见错误 / 代码审查重点不要让 else 匹配错层；始终使用大括号。多个规则有优先级时不能随意调整顺序。复杂三元表达式可读性很差。
动手练习 / 学会的标准分别把 quantity 改成 0、8、2，预测并核对结果。

08 · switch 与状态分发

P0 · 必须掌握

1. 这是什么？企业为什么用？

switch 适合同一个变量与多个固定值匹配。Java 17 支持箭头式 switch 表达式，直接返回值且不会发生传统 case 的贯穿。老项目常见冒号写法与 break。

2. 完整可运行代码

Demo08.java · JDK 17
public class Demo08 {
    public static void main(String[] args) {
        String status = "PAID";
        String label = switch (status) {
            case "NEW" -> "待支付";
            case "PAID" -> "待发货";
            case "DONE" -> "已完成";
            default -> "未知状态";
        };
        System.out.println(label);
        // 老代码中的传统写法
        switch (status) {
            case "PAID": System.out.println("发送发货提醒"); break;
            default: System.out.println("无需提醒");
        }
    }
}

3. 运行结果（实际执行）

待发货
发送发货提醒

4. 代码解析与实际用途

订单状态转换为前端展示文本时可用 switch。箭头式每个分支互斥，default 处理剩余情况。复杂业务分支仍可以用 if 或独立方法。

常见错误 / 代码审查重点传统 switch 的 case 若缺少 break 可能继续执行下一分支；Java 17 的 String switch 遇到 null 会抛异常，先校验。不要把所有业务都塞进一个巨大 switch。
动手练习 / 学会的标准添加 SHIPPED 和 CANCELLED 两个分支；尝试未知值。

09 · 普通 for 循环与增强 for

P0 · 必须掌握

1. 这是什么？企业为什么用？

for 用于重复执行。普通 for 由初始化、条件、更新组成；增强 for（for-each）用于直接遍历数组或实现 Iterable 的集合。需要下标时用普通 for，只关心元素时用增强 for。

2. 完整可运行代码

Demo09.java · JDK 17
public class Demo09 {
    public static void main(String[] args) {
        int[] quantities = {2, 5, 3};
        for (int i = 0; i < quantities.length; i++) {
            System.out.println("第" + (i + 1) + "条: " + quantities[i]);
        }
        int total = 0;
        for (int qty : quantities) {
            total += qty;
        }
        System.out.println("总数量=" + total);
    }
}

3. 运行结果（实际执行）

第1条: 2
第2条: 5
第3条: 3
总数量=10

4. 代码解析与实际用途

第一段遍历订单数量数组，按下标打印；第二段累加总数量。i++ 每轮结束后执行，不是进入循环立即执行。for (int qty : quantities) 每次把当前元素赋给 qty。

逐轮跟踪i=0 → quantities[0]=2 → total 可累加；i=1 → 5；i=2 → 3；i=3 时条件为 false，退出。普通 for 适合读取第几个元素；增强 for 直接取得值。
常见错误 / 代码审查重点条件写成 i <= quantities.length 会越界。增强 for 中修改基本类型循环变量不会改数组；遍历集合时直接结构性删除可能报错。
动手练习 / 学会的标准算出数组中的最大数量与总量，分别用两种 for 实现。再打印第 1、2、3 条订单编号（显示编号从 1 开始）。

10 · while、do while、break 与 continue

P0 · 必须掌握

1. 这是什么？企业为什么用？

17 · 继承、extends、super 与方法重写

P0 · 必须掌握

1. 这是什么？企业为什么用？

P0 · 必须掌握

1. 这是什么？企业为什么用？

Map 的 keySet 返回键视图，values 返回值视图，entrySet 返回键值对视图。统计频次可用 getOrDefault 或 merge；分组可用 computeIfAbsent 创建列表后添加元素。

2. 完整可运行代码

Demo31.java · JDK 17
import java.util.List;
import java.util.ArrayList;
import java.util.Map;
import java.util.HashMap;
import java.util.TreeMap;

public class Demo31 {
    public static void main(String[] args) {
        List<String> levels = List.of("INFO", "ERROR", "INFO");
        Map<String, Integer> counts = new HashMap<>();
        for (String level : levels) counts.merge(level, 1, Integer::sum);
        for (Map.Entry<String, Integer> e : new TreeMap<>(counts).entrySet()) {
            System.out.println(e.getKey() + "=" + e.getValue());
        }
        Map<String, List<String>> grouped = new HashMap<>();
        grouped.computeIfAbsent("order", key -> new ArrayList<>()).add("CPU");
        grouped.computeIfAbsent("order", key -> new ArrayList<>()).add("TIMEOUT");
        System.out.println(grouped.get("order"));
    }
}

import java.util.ArrayList;

53 · 共享状态、synchronized 与 AtomicInteger

P1 · 常用进阶

1. 这是什么？企业为什么用？

多线程同时读写共享状态可能产生竞态。count++ 包含读取、计算、写入多个步骤，并非原子操作。synchronized 可保护临界区，AtomicInteger 支持原子计数。volatile 提供可见性和相应有序性，但不让 count++ 自动变成原子操作。

2. 完整可运行代码

Demo53.java · JDK 17
import java.util.concurrent.atomic.AtomicInteger;

public class Demo53 {
    public static void main(String[] args) throws Exception {
        AtomicInteger count = new AtomicInteger();
        Runnable work = () -> { for (int i = 0; i < 1000; i++) count.incrementAndGet(); };
        Thread a = new Thread(work), b = new Thread(work);
        a.start(); b.start(); a.join(); b.join();
        System.out.println(count.get());
        Counter counter = new Counter(); counter.increment();
        System.out.println(counter.get());
    }

    static class Counter {
        private int value;
        synchronized void increment() { value++; }
        synchronized int get() { return value; }
    }
}

3. 运行结果（实际执行）

2000
1

4. 代码解析与实际用途

两个线程各执行 1000 次原子递增，join 后结果为 2000。另一个 Counter 使用 synchronized 方法保护其字段；读取也同步。锁对象必须一致才有效。

常见错误 / 代码审查重点不要把局部线程安全等同于完整业务事务。AtomicInteger 只保证单个原子操作，复杂检查再更新可能仍需锁或 CAS 循环。锁范围要合理，避免持锁进行慢 IO。
动手练习 / 学会的标准将 atomic 改为共享普通字段自增（仅实验），多次运行对比；再用 Counter.increment 恢复正确结果。

55 · CompletableFuture：并行任务与结果组合

P1 · 常用进阶

1. 这是什么？企业为什么用？

CompletableFuture 支持组合异步任务。supplyAsync 提交有返回值任务，thenApply 转换结果，thenCombine 组合两个独立结果，exceptionally 可在失败后恢复默认值。依赖关系不同决定串行或并行。

2. 完整可运行代码

Demo55.java · JDK 17
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;
import java.util.concurrent.CompletableFuture;

public class Demo55 {
    public static void main(String[] args) throws Exception {
        ExecutorService pool = Executors.newFixedThreadPool(2);
        try {
            CompletableFuture<String> metrics = CompletableFuture.supplyAsync(() -> "CPU=80%", pool);
            CompletableFuture<String> alerts = CompletableFuture.supplyAsync(() -> "告警=2", pool);
            String result = metrics.thenCombine(alerts, (m, a) -> m + ", " + a)
                    .orTimeout(2, TimeUnit.SECONDS).join();
            System.out.println(result);
        } finally {
            pool.shutdown();
        }
    }
}

常见错误 / 代码审查重点不要把每次 thenApply 理解成新线程；不带 Async 的回调可能在完成任务的线程或调用线程执行。生产使用独立合适的线程池，并配置 HTTP 客户端自身超时。不能随意吞掉错误当成成功。

P1 · 常用进阶

1. 这是什么？企业为什么用？

import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import com.sun.net.httpserver.HttpServer;

public class Demo57 {
    public static void main(String[] args) throws Exception {
        HttpServer server = HttpServer.create(new InetSocketAddress("127.0.0.1", 0), 0);
        server.createContext("/health", exchange -> {
            byte[] data = "{\"status\":\"ok\"}".getBytes(StandardCharsets.UTF_8);
            exchange.getResponseHeaders().set("Content-Type", "application/json; charset=utf-8");
            exchange.sendResponseHeaders(200, data.length);
            try (OutputStream out = exchange.getResponseBody()) { out.write(data); }
        });
        server.start();
        try {
            String url = "http://127.0.0.1:" + server.getAddress().getPort() + "/health";
            HttpClient client = HttpClient.newBuilder().connectTimeout(Duration.ofSeconds(2)).build();
            HttpRequest request = HttpRequest.newBuilder(URI.create(url)).timeout(Duration.ofSeconds(3)).GET().build();
            HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
            System.out.println(response.statusCode());
            System.out.println(response.body());
        } finally { server.stop(0); }
    }
}

P0 · 必须掌握

1. 这是什么？企业为什么用？

这是纯 Java SE 项目中的最小业务闭环，不使用 Spring 或数据库。目的是让你读懂典型 Controller → Service → Repository 的调用、对象数据转换、异常和集合。main 模拟入口，Service 处理业务，Repository 隔离存储；在真实项目中可替换成 MyBatis 实现。

2. 完整可运行代码

Demo58.java · JDK 17
import java.util.List;
import java.util.ArrayList;
import java.util.Map;
import java.util.LinkedHashMap;

public class Demo58 {
    public static void main(String[] args) {
        OrderService service = new OrderService(new MemoryRepository());
        service.create("O1", 2);
        service.create("O2", 3);
        service.cancel("O1");
        System.out.println(service.list(Status.NEW));
        System.out.println(service.list(Status.CANCELLED));
        try { service.cancel("O1"); }
        catch (IllegalStateException e) { System.out.println(e.getMessage()); }
    }

    enum Status { NEW, CANCELLED }
    record Order(String id, int quantity, Status status) {}
    record OrderView(String id, int quantity, String status) {}
    interface OrderRepository {
        Order find(String id);
        void save(Order order);
        List<Order> findAll();
    }
    static class MemoryRepository implements OrderRepository {
        private final Map<String, Order> data = new LinkedHashMap<>();
        public Order find(String id) { return data.get(id); }
        public void save(Order order) { data.put(order.id(), order); }
        public List<Order> findAll() { return new ArrayList<>(data.values()); }
    }
    static class OrderService {
        private final OrderRepository repo;
        OrderService(OrderRepository repo) { this.repo = repo; }
        void create(String id, int quantity) {
            if (id == null || id.isBlank() || quantity <= 0) throw new IllegalArgumentException("参数非法");
            if (repo.find(id) != null) throw new IllegalArgumentException("订单已存在");
            repo.save(new Order(id, quantity, Status.NEW));
        }
        void cancel(String id) {
            Order order = repo.find(id);
            if (order == null) throw new IllegalArgumentException("订单不存在");
            if (order.status() != Status.NEW) throw new IllegalStateException("当前状态不可取消");
            repo.save(new Order(order.id(), order.quantity(), Status.CANCELLED));
        }
        List<OrderView> list(Status status) {
            return repo.findAll().stream().filter(o -> o.status() == status)
                .map(o -> new OrderView(o.id(), o.quantity(), o.status().name())).toList();
        }
    }
}

4. 代码解析与实际用途

创建订单前验证数量和 ID 唯一性；取消只允许 NEW 状态。查询列表使用 Stream 按状态过滤并转换为响应。Repository 负责存取，Service 负责规则。这里使用不可变 record，状态变化时创建新对象。演示单线程逻辑，不具备生产数据库事务、鉴权及并发一致性。

按调用链定位功能main 调 create → OrderService 检查参数、重复订单 → OrderRepository.find → MemoryRepository.data.get → save 存入 Map。cancel 同样先查数据，再校验状态、存储新对象。list 则走 findAll → filter → map → toList。想加筛选条件先改 list，而不是先改仓储。
常见错误 / 代码审查重点不要把状态校验仅放在 Controller；其他调用可能绕过。不要直接把数据库实体全部返回前端。Map 内存数据重启会丢失，find 后 save 不是并发原子操作。
